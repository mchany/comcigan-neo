# Parser Health 신뢰성·진단 개선 설계

날짜: 2026-11-17
기준: main b1524f0bde000cd55e9807519082efd490cd9f44 (PR #27 병합)
상태: 검토용, 사용자 승인 전 구현 금지

## 목적과 성공 조건

학교 검색·두 게시 기간의 조회를 실제 Kotlin 클라이언트로 검사하면서 정상 미게시, 판단 불가, 장애를 구분한다. 일시적인 통신 실패의 불필요한 이슈를 줄이되 구조 변경은 같은 실행에서 보고한다. 앱의 조회 동작과 UI는 유지한다.

전체 성공은 필수 검사가 모두 HEALTHY 또는 근거가 확인된 UNPUBLISHED인 경우뿐이다. INDETERMINATE·FAIL·실패로 인한 SKIPPED는 성공으로 바꾸지 않는다. 빈 데이터만으로 미게시를 확정하지 않는다.

## 조사한 현행 동작

- LiveCheck.kt는 Triple 기반 PASS/FAIL 표를 만들며 첫 실패에서 나머지 검사를 중단한다.
- 일반 IOException에는 DNS/타임아웃뿐 아니라 403/429 이외 HTTP 오류와 비정상 본문도 포함된다.
- StructureChanged는 서비스 페이지 해석과 응답 디코딩/파싱에서 공용으로 사용된다.
- ComciganParser.timetable은 빈 객체 또는 시작일 누락을 TimetableUnavailable로 처리한다.
- ComciganClient.fetch도 검증된 초기 스냅샷의 게시 목록에 선택 기간이 없으면 같은 예외를 사용한다.
- Health는 week=1의 모든 TimetableUnavailable를 PASS로 받아들이므로 위 두 출처를 구분하지 못한다.
- 시작일/학급/교시 검증 후 수업이 하나도 없으면 실패한다. 방학을 입증하는 별도 필드는 현재 확인하지 못했다.
- PR #27의 publishedWeekStarts(date), 날짜 변경 시 1회 재조회 및 날짜 오류 진단은 main에 포함돼 있다.
- parser-health.cjs는 main workflow_dispatch의 단계 실패마다 한 열린 봇 이슈를 생성/갱신하며 성공 실행은 처리하지 않는다. 자동 종료는 없다.
- 워크플로 concurrency는 parser-health, cancel-in-progress=false이며 PR도 검사를 실행한다.
- Workers 소스/설정은 저장소에 없다. 저장소에서 확인 가능한 계약은 workflow_dispatch의 source, scheduled_time 입력이다. 결과를 Worker에 전송하는 코드는 없다.
- README 배지는 GitHub Actions 실행의 성공/실패를 표시한다. 별도 서비스 상태 API가 아니다.

관찰된 코드 경로와 과거 실행의 직접 원인은 구분한다. 보존되지 않은 원본 응답·예외에 근거한 과거 원인 확정은 하지 않는다.

## 사용자 결정과 접근 방식

1. 선택: 한 실행 안에서 일시적 오류를 제한적으로 재확인한다.
2. 대안: 여러 예약 실행의 연속 실패 후 이슈 생성. 오탐을 더 줄일 수 있지만 최대 6시간 이상 감지가 늦어지고 실행 간 상태 관리가 필요하여 선택하지 않았다.
3. 이슈 종료는 사용자가 수동으로 한다. 자동 종료·재열기는 구현하지 않는다.

새 외부 의존성이나 상태 저장소를 추가하지 않는다. 기존 Kotlin 직렬화, Node 내장 모듈, GitHub API만 사용한다.

## 상태와 분류

단계 결과와 오류 유형은 분리한다.

단계 결과:
- HEALTHY: 조회 및 의미 검증 성공.
- UNPUBLISHED: 검증된 게시 기간 자료에 요청 기간이 없다는 근거가 확인됨.
- INDETERMINATE: 빈 응답·시작일 누락·수업 없음 등으로 정상 미게시와 이상 응답을 구분할 수 없음.
- FAIL: 명확한 통신/서버/프로토콜/파싱/검증 오류.
- SKIPPED: 선행 학교 검색 실패로 시간표 조회 불가 등 명시적인 의존성 생략.

오류 유형:
- NETWORK_ERROR: DNS, 연결 실패, 타임아웃 등 실제 전송 오류.
- SERVER_ERROR: 비정상 HTTP 상태. 상태 코드와 재시도 여부를 별도 필드로 기록.
- PROTOCOL_ERROR: 서비스 페이지의 요청 경로, 키 표현, 토큰 등 지원하지 않는 서비스 구조.
- PARSE_ERROR: 응답 디코딩·인증·JSON 및 데이터 해석 실패.
- VALIDATION_ERROR: 파싱된 자료의 학급·날짜·교시·과목 등 의미 검증 실패.
- UNKNOWN_ERROR: 위 유형으로 안전하게 분류할 수 없는 오류.
- ENVIRONMENT_ERROR: checkout/JDK/Gradle/회귀 검증/결과 파일 누락 등 실서버 파서 장애와 구분해야 하는 검사 환경·검증 파이프라인 실패.

취소 예외는 일반 오류로 삼켜 재시도하지 않고 전파한다. 임의 예외 메시지, cause 전체, 원본 응답, 토큰/키는 출력하지 않는다.

## 예외 출처 구분과 앱 호환성

문자열 메시지 매칭으로 원인을 추측하지 않는다. 기존 예외에 기본값이 있는 출처/근거 필드를 추가하거나 기존 예외 계층 안에서 타입을 세분화한다. 기존 호출 및 catch 동작은 유지한다.

- HTTP 오류의 상태 코드를 보존하고 응답 본문 한계 오류도 전송 오류와 구분한다.
- 서비스 페이지 오류와 응답 디코딩/파싱 오류를 발생 지점에서 구분한다.
- TimetableUnavailable에는 게시 목록으로 확인된 부재인지, 본문만으로 판단할 수 없는 상태인지 구분할 근거를 추가한다.
- 카탈로그 기반 UNPUBLISHED는 초기 스냅샷 파싱과 게시 기간 검증이 성공한 후에만 가능하다.
- 빈 객체/시작일 누락을 앱에서 다루는 기존 예외 타입은 유지하되 Health에서는 INDETERMINATE로 기록한다.
- 합법적으로 파싱된 수업 0개 스냅샷도 INDETERMINATE로 남긴다. 요일/방학이라는 추측으로 HEALTHY나 UNPUBLISHED로 바꾸지 않는다.
- 파서의 성공 데이터, 반환 모델, 재시도 대상 예외 계층 및 앱 사용자 오류 처리를 의도적으로 변경하지 않는다.

## 날짜·주차 검증

PR #27의 게시 기간 기준과 한국 시간 기준을 유지한다. 서버 요청 번호를 달력 주차로 대체하거나 연속 번호로 가정하지 않는다.

기존 자정 경계 재조회 1회 상한을 유지하며 UNPUBLISHED/INDETERMINATE 결과도 조회 전후 날짜의 일관성을 확인한다. 반복 날짜 변경은 판정 실패로 남긴다. 검증되지 않은 다른 기간의 스냅샷을 미게시로 처리하지 않는다.

명시적인 게시 목록 부재는 week=0/1 모두 근거에 따라 UNPUBLISHED로 분류할 수 있다. 이전 형식의 캘린더 대체 동작은 보존하며 근거 없는 부재를 확정하지 않는다.

## 단계 실행과 재확인

단계: 정확 학교 검색, 없는 학교 검색, 첫 게시 기간, 두 번째 게시 기간.
실패한 단계와 무관한 후속 검사는 계속하며 학교를 특정할 수 없으면 시간표 단계는 이유를 기록한 SKIPPED로 남긴다.

Health 단계 단위 재시도는 NETWORK_ERROR 또는 HTTP 500/502/503/504에만 최대 1회, 짧은 고정 대기(제안 1초) 후 수행한다. 최종 결과에 실패한 첫 시도와 재시도 결과를 모두 남긴다. HTTP 403/429 및 그 밖의 상태, 프로토콜/파싱/검증/판단 불가는 Health 계층에서 추가 재시도하지 않는다.

기존 클라이언트의 서비스 정보 갱신·기간 변경 재시도는 유지한다. Health의 attempts는 단계 시도 횟수이며 실제 HTTP 요청 수로 표시하지 않는다. 날짜 경계 재조회 횟수는 따로 기록한다. 무제한 중첩 재시도는 없으며 각 계층 상한을 테스트한다.

## 구조화 결과와 Summary

기존 Markdown Summary를 유지하면서 별도 JSON 파일을 추가한다. 새 결과 파일 경로는 PARSER_HEALTH_RESULT 환경 변수로 전달하고 스키마 버전을 1로 고정한다.

최소 필드:
- schemaVersion, checkedAt(ISO instant), timezone(Asia/Seoul), target(학교·학급), overall.
- steps: id, status, errorType, code, referenceDate, week(0/1 또는 null), expectedStart/actualStart(해당 시), attempts.
- attempts: 시도 번호, 상태·오류 유형·고정 진단 코드, 날짜 경계 재조회 횟수.
- 메시지는 검증된 고정 문구와 날짜/정수 등 제한된 값으로 구성한다.
- 실행하지 못한 단계는 성공으로 생략하지 않고 SKIPPED로 포함한다.

파일은 완전한 결과만 사용하도록 원자적으로 기록한다. 출력/파일 기록 자체 실패도 프로세스 실패로 남긴다. Node는 파일 크기·스키마·필수 단계·상태 조합을 검증하고 누락/비정상 파일을 정상·복구 증거로 쓰지 않는다.

Summary 표에는 단계, 상태, 오류 유형, 기준 날짜/주차, 재시도 결과를 표시한다. CLI는 전체 HEALTHY/UNPUBLISHED만 종료 코드 0이며 INDETERMINATE/FAIL/필수 SKIPPED는 비정상 종료한다. 배지는 실행 결과를 그대로 보여주며 서비스 정상 여부를 과장하지 않도록 README에 설명한다.

## 자동 Issue 보고와 복구 추적

기존 소유자/저장소/main/workflow_dispatch 제한, 봇 작성자 확인, 전용 마커, 전체 열린 이슈 페이지 조회, concurrency를 유지한다. PR·다른 브랜치·포크에서는 Issue를 쓰지 않는다.

- 제한 재확인으로 회복한 단계는 정상 결과로 기록하고 새 이슈를 생성하지 않는다.
- 지속 실패·판단 불가·환경 오류는 유형이 표시된 기존 단일 운영 이슈를 생성/갱신한다. 판단 불가나 환경 오류를 확정적인 파서 장애라고 서술하지 않는다.
- 첫 실패와 최신 관측을 보존해 어떤 단계가 변했는지 파악할 수 있게 한다.
- 동일 실행/attempt/결과를 반복 처리해도 추가 쓰기하지 않는다.
- 새로운 유형의 장애도 별도 중복 이슈가 아니라 기존 열린 자동 이슈에 반영한다.
- 모든 필수 단계가 HEALTHY인 완전한 성공 실행만 기존 이슈에 복구 확인을 기록한다.
- UNPUBLISHED를 포함한 실행은 정상 미게시 사실은 기록할 수 있지만 시간표 파싱 복구가 확인됐다고 쓰지 않는다.
- INDETERMINATE, 실패, 환경 오류, 취소, 단계 생략은 복구 확인으로 사용하지 않는다.
- 이슈는 자동으로 닫거나 재열지 않는다. 사용자가 닫은 뒤 발생한 새 장애는 현재 정책처럼 새 이슈로 보고한다.
- 순서가 뒤바뀐 옛 실행/옛 attempt로 최신 상태를 덮지 않도록 실행 식별자를 비교한다.
- API 조회/쓰기 실패는 명확히 실패로 남기고 우회 생성·자동 쓰기 재시도를 하지 않는다.

성공 실행도 보고 단계를 실행할 수 있도록 워크플로 조건을 조정한다. 결과 파일이 없는 준비/빌드 실패는 ENVIRONMENT_ERROR로 보고한다. 취소된 실행이나 checkout 실패로 스크립트가 없는 경우의 보고 불가능성은 문서에 명시한다.

## Workers 및 배지 계약

workflow_dispatch 입력 이름·형식과 workflow 파일명, job명, README 배지 주소를 유지한다. Worker 배포·설정 변경은 하지 않는다. 저장소 외 Worker 구현은 미확인 사항으로 표시하며 로컬 테스트에서는 기존 source/scheduled_time 입력으로 호환성을 검증한다.

## 변경 범위와 비목표

허용: core/comcigan의 Health 코드/테스트, 분류에 필요한 기존 예외·오류 발생 지점의 최소 수정, parser-health workflow/Node 도구/테스트, README·운영 문서·설계/계획 문서.
금지: Android UI/기능 변경, core:model의 달력·캐시 정책 변경, 급식/알림/위젯, 앱 버전 변경, APK 빌드·서명·배포, Worker 배포, 불필요한 의존성 추가.
별도 브랜치 parser-health-diagnostics로 작업하고 검증 후 push와 PR을 생성한다. merge는 하지 않는다.

## 검증

외부 통신 없는 회귀 검증:
- 기존 PR #27 테스트 전부 유지.
- 정상 검색·두 기간, 확정 미게시, 모호한 빈 객체/시작일 누락/수업 없음.
- DNS/타임아웃, HTTP 403/429/500/502/503/504 및 기타 상태 분류.
- 서비스 구조 변경, 인증/디코딩/JSON/필수 필드 오류, 의미 검증 오류.
- 자정·일요일/월요일·연말·가변 게시 요청 번호.
- 일시 실패 후 정상·재실패·재시도 상한·취소 전파.
- 결과 JSON/Markdown 생성·누락/잘림·비정상 스키마·민감 메시지 마스킹.
- 같은 장애의 반복 보고·유형 변경·중복 처리·새로운 실행·이전 실행/attempt.
- 실제 완전 성공 시 복구 기록, 미게시/판단 불가/환경 실패에서 잘못된 복구 기록 방지.
- 수동 이슈/PR 보호, 전체 페이지 조회, API 실패 시 우회 생성 없음.
- workflow shell의 Summary와 JSON 파일 경로 전달, 기존 Worker 입력 유지.
- 기존 모델·파서 JVM 테스트와 Node 관련 테스트, workflow 문법 및 diff 범위 검사.

명시적으로 분리한 실서버 검증:
실제 Kotlin CLI로 정확 학교 검색·빈 검색·두 게시 기간 조회를 실행한다. 외부 상태에 따른 실패는 로컬 회귀 실패와 구분해 기록한다. 공개 테스트 이슈 생성이나 실제 장애 강제 주입은 하지 않는다.

사용자 지정 문제 분석/변경/검증/호환성/결론 항목과 미검증 사항, PR 링크를 제공한다. 실행 증거 없이 완료·통과를 주장하지 않는다.

## 구현자가 정할 수 있는 사항

구체적인 내부 타입명·함수 분리·동일 계층 내 파일 분할, JSON 직렬화 세부사항, 제한값은 기존 스타일에 맞춰 정한다. 위 상태 의미, 재시도 상한, 수동 종료 정책, 데이터 보안, 호환 계약은 바꾸지 않는다.
