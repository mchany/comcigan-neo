# 나이스 급식 조회 추가 구상안

조사일: 2026-10-27 KST. 대상: 0.1.0-beta Kotlin/Compose Android 앱의 급식 확장. 이 문서는 초기 조사와 설계 제안이다. 이후 사용자 요청에 따라 neis.kt를 참고한 `core:neis`와 급식 기능을 구현했으며 현재 상태와 검증 결과는 README 및 검증 기록을 참고한다.

## 권장 방향

공식 NEIS Open API를 기존 OkHttp와 kotlinx.serialization으로 호출하는 작은 `core:neis` 모듈을 추가한다. 오늘 화면에 중식 카드를 넣고, 날짜별 조식·중식·석식과 상세 정보를 확인하는 급식 탭을 제공한다. 최초 급식 사용 때 컴시간 학교와 나이스 학교를 연결하고 이후에는 저장한 코드를 사용한다.

전용 라이브러리를 반드시 사용한다면 Keis와 neis.kt를 먼저 검토한다. 다만 현재 앱이 학교 검색과 급식 두 API만 필요로 하고 이미 HTTP·JSON 의존성을 갖고 있으므로, 직접 연결이 의존성과 오류 처리 범위를 작게 유지하기 쉽다는 판단이다.

## 현재 앱과 연결 지점

- `app`: Kotlin/Jetpack Compose Material 3, Android 8.0 이상, JDK 17. 현재 하단 탐색은 오늘 / 주간 / 설정이다.
- `core:model`: 컴시간 `School(code: Int, name, region)`과 학급 선택 모델. NEIS 학교 코드를 저장하는 필드는 없다.
- `core:comcigan`: OkHttp 4.12.0, 코루틴, kotlinx.serialization 사용.
- `core:data`: Room DB 버전 1의 시간표 캐시와 DataStore 설정. 급식 캐시를 추가하면 명시적인 마이그레이션이 필요하다.
- 현재 계정·앱 백엔드가 없다. 급식 조회 실패는 기존 시간표 표시를 막지 않도록 별도 상태로 관리한다.

## 실제 응답 확인

인증키 없이 허용되는 샘플 요청으로 아래를 확인했다. 한 학교의 제한적인 프로토콜 확인이며 전체 학교 지원, 인증키 호출, 페이지네이션 전체 수집을 검증한 것은 아니다.

| 요청 | 결과 |
|---|---|
| `schoolInfo`, 학교명 중일고등학교 | 정상, 1건. 교육청 `G10`, 표준학교코드 `7430065`, 대전 유성구 주소 반환 |
| `mealServiceDietInfo`, 위 코드, `MLSV_YMD=20261027` | 정상, 중식·석식 2건. 메뉴·열량·영양·원산지 반환 |
| 같은 학교, `MLSV_YMD=20261025` | 최상위 `RESULT.CODE=INFO-200`, 해당 데이터 없음 |
| 같은 학교, `MLSV_FROM_YMD=20261026`, `MLSV_TO_YMD=20261101`, `pSize=100` | `list_total_count=9`, 실제 반환 5건. 키 없는 요청으로 주간 전체 자료를 얻었다고 판단하면 안 됨 |

중식 응답의 메뉴에는 `<br/>`, `나가사키짬뽕/면 (2.5.6.9.10.16.17.18)` 같은 알레르기 번호가 포함되었다. 열량은 `915.9 Kcal`처럼 문자열이었다.

## 공식 API 사용 설계

학교 검색: `GET https://open.neis.go.kr/hub/schoolInfo`

- `KEY`, `Type=json`, `pIndex`, `pSize`, `SCHUL_NM` 사용.
- `ATPT_OFCDC_SC_CODE`(교육청), `SD_SCHUL_CODE`(표준학교코드), `SCHUL_NM`, `LCTN_SC_NM`, `ORG_RDNMA` 등을 보관한다.
- 코드는 문자열로 취급한다. 컴시간의 `School.code`를 NEIS 코드로 전달하지 않는다.

급식: `GET https://open.neis.go.kr/hub/mealServiceDietInfo`

- 학교 코드 쌍과 `MLSV_YMD=yyyyMMdd` 또는 `MLSV_FROM_YMD`/`MLSV_TO_YMD`를 사용한다.
- `MMEAL_SC_CODE`: 1 조식, 2 중식, 3 석식. 기간 조회는 식사 종류 전체를 받아 화면에서 나눈다.
- `DDISH_NM` 메뉴, `CAL_INFO` 열량, `NTR_INFO` 영양, `ORPLC_INFO` 원산지를 사용한다. 원문도 보존한다.
- `LOAD_DTM`은 포털 연계 일자다. 학교가 메뉴를 수정한 정확한 시각이나 앱의 최종 확인 시각으로 표시하지 않는다.
- HTTP 성공과 데이터 성공을 구분한다. 정상 데이터의 `head.RESULT`와 자료 없음·오류의 최상위 `RESULT` 모두 읽는다. `INFO-200`은 자료 없음이며 통신 실패로 바꾸지 않는다.
- 인증키 호출 시 `list_total_count`와 실제 행 수를 확인해 페이지를 수집한다. 불완전한 결과를 완전한 주간 자료로 캐시하지 않는다.

## 학교 연결 흐름

기존 시간표 설정을 마친 사용자에게 급식 기능을 처음 열 때만 연결을 안내한다.

1. 저장한 컴시간 학교 이름으로 NEIS 후보를 검색한다. 지역은 후보 정렬·검증에 사용한다.
2. 학교명·교육청·도로명주소를 보여 주고 사용자가 학교를 확인한다. 동명 학교는 첫 번째 검색 결과로 자동 확정하지 않는다.
3. `comciganSchoolCode → NeisSchoolRef(officeCode, schoolCode, name, address)`를 별도 저장한다. 첫 버전은 후보가 하나여도 확인을 받는 방식으로 오연결을 줄인다.
4. 후보가 없거나 이름이 바뀌었으면 직접 검색을 제공한다. 설정에서 연결 변경·해제 가능.
5. 같은 학교에서 학년·반만 변경하면 연결을 재사용한다. 학교가 바뀌면 해당 학교의 연결만 적용하고 이전 학교 요청 결과가 새 화면에 반영되지 않게 한다.

## 화면 구상

하단 탐색을 **오늘 / 주간 / 급식 / 설정**으로 확장한다. 기존 숫자 인덱스 조건 대신 탭 enum 또는 sealed 타입을 사용해 새로고침과 설정 화면 분기가 틀어지지 않게 한다.

- **오늘:** 날짜·수업 요약 다음에 오늘 중식 카드. 메뉴와 열량을 표시하고 탭하면 급식 화면의 같은 날짜로 이동. 중식이 없는 날 다른 식사를 중식으로 바꾸어 보여주지 않는다.
- **급식:** 날짜 선택과 이전/다음 날짜, 오늘로 이동. 중식 기본 선택, 조식·석식 전환. 주말도 조회 가능하며 학교별 운영 여부를 추측하지 않는다.
- **상세:** 메뉴 줄바꿈, 원문 알레르기 번호, 번호 설명, 열량. 영양정보·원산지는 펼치기 영역으로 제공한다. 출처는 나이스 교육정보 개방 포털로 표시한다.
- **설정:** 급식 학교 확인·변경, 급식 캐시 삭제. 기존 전체 캐시 삭제는 시간표와 급식 모두 포함하도록 의미를 명확히 한다.

예시 카드:

```text
오늘 중식                           915.9 kcal
강황쌀밥
나가사키짬뽕/면 (2.5.6.9.10.16.17.18)
배추겉절이 (9.13)
소고기숙주볶음 (5.6.13.16.18)
장어구이 (5.6.13)
                         급식 자세히 보기 →
```

초기 버전에서는 알레르기 번호와 공식 번호 설명을 제공한다. 음식 이름의 모든 숫자를 삭제하지 않으며 모호한 번호는 원문을 유지한다. 개인별 알레르기 설정·메뉴 강조는 후속 기능으로 둔다.

화면 상태는 연결 전 / 로딩 / 정상 / 해당 날짜에 등록된 급식 정보 없음 / 저장 자료 표시 중 / 오류로 구분한다. 자료 없음만으로 휴교·방학·급식 미실시를 단정하지 않는다. 오래된 자료는 조회 날짜와 마지막 성공 시각을 함께 표시한다.

## 모델·저장·동기화

- `core:neis`: 순수 Kotlin/JVM `NeisClient`, DTO, 응답 파서와 오류 모델. 취소 가능한 네트워크 호출, 타임아웃, URL 파라미터 인코딩 지원. UI나 Room에 의존하지 않는다.
- `core:model`: `NeisSchoolRef`, `MealType`, `MealDay`/`MealEntry`, `MealSnapshot`. 원문 메뉴와 표시용 메뉴를 분리하고 열량 누락·알 수 없는 식사 코드를 처리한다.
- `core:data`: `MealRepository`, DataStore 학교 연결, Room 급식 캐시. 시간표 DB를 확장한다면 1→2 명시적 migration으로 기존 시간표와 설정을 보존한다.
- 캐시 행은 교육청+표준학교코드+날짜 단위로 식사 목록과 `fetchedAt`을 저장한다. 정상적인 빈 목록도 캐시하되 짧은 만료 시간을 둔다.
- 초기 조회 단위는 월~일 한 주. 오늘 카드는 해당 주 캐시를 재사용한다. 급식 화면에서 다음 주로 넘어가면 필요한 주만 추가 조회한다.
- 만료 정책 제안: 현재·미래 주 6시간, 자료 없음 1시간. 만료 시 앱에서 해당 화면을 보는 동안 갱신하고 수동 새로고침은 만료 시간과 무관하게 요청한다. 정확한 주기는 실제 호출량을 보고 조정한다.
- 네트워크 실패 시 기존 캐시를 유지한다. 완전한 주간 응답을 얻은 뒤 트랜잭션으로 교체해, 취소된 메뉴가 오래 남거나 부분 응답이 전체를 덮어쓰지 않게 한다.
- 같은 학교·주의 동시 요청을 합치고 학교 변경 시 이전 요청을 취소한다. Asia/Seoul 기준 날짜를 기존 `SchoolZone`과 공유한다. 백그라운드 주기 작업은 첫 범위에서 제외한다.

## 인증키와 배포

[공식 안내](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17320190722180924242823&infSeq=2)는 인증키 없는 요청을 5건 샘플로 제한하고 실제 호출에는 인증키를 사용하도록 명시한다. 따라서 무키 조회를 정식 기능의 기반으로 삼지 않는다. [공공데이터포털](https://www.data.go.kr/data/15139198/openapi.do)은 무료 서비스로 안내하며 트래픽은 기관 정책에 따라 달라질 수 있다고 명시한다. 고정된 일일 한도를 임의로 가정하지 않는다.

| 방식 | 장점 | 제약·적용 제안 |
|---|---|---|
| 앱에서 공식 API 직접 호출, 개발자 발급 키를 빌드 시 주입 | 현재 백엔드 없는 구조 유지, 사용자의 별도 키 입력 불필요 | APK에서 키 추출 가능. 저장소·로그에서는 제외해도 비밀로 보호되지는 않음. 키 사용 정책과 실제 허용 호출량 확인 후 소규모 베타에 적용하는 안 |
| 사용자별 키 입력 | 공용 키를 APK에 넣지 않음 | 발급·입력 과정이 학생용 앱 사용성을 떨어뜨림. 개발·검증용 옵션으로 적합 |
| 키를 서버에 두고 앱은 캐시 프록시 호출 | 서버에서 키 관리, 학교·주별 캐시 공유와 호출량 통제 | 별도 호스팅·운영 필요. 공개 배포 규모가 커지거나 공용 키 노출을 허용할 수 없을 때 선택 |

우선 직접 호출로 모듈을 설계하고 키는 외부 설정에서 주입한다. 공개 배포 전 키 노출 허용 여부와 운영 한도를 확인하는 것을 배포 조건으로 둔다. 프록시를 선택하더라도 UI·캐시 코드를 유지할 수 있게 데이터 소스 인터페이스를 둔다. 이번 조사에서 키 발급·계정 등록·서버 배포는 수행하지 않았다.

## 구현 순서와 완료 기준

1. **API 기반:** 인증키 준비, `core:neis` 학교·급식 조회 및 파서. 정상/빈 결과/인증 오류/호출 제한/구조 변경 fixture와 HTML 줄바꿈·메뉴 숫자 보존 테스트. 인증키로 5건 이상 기간 조회와 페이지 처리 실서버 확인.
2. **학교 연결과 캐시:** 후보 확인 UI, 연결 저장, 학교 변경 시 응답 격리, Room migration. 기존 0.1.0-beta 사용자 설정·시간표 유지 확인.
3. **UI 통합:** 오늘 중식 카드, 급식 탭·날짜 이동·식사 전환·상세. 시간표 새로고침과 급식 새로고침을 구분하고 데이터 제공 실패를 각각 표시.
4. **배포 검증:** 동명 학교, 조식 없는 학교, 주말 급식, 미등록 일자, 오프라인 재진입, 자정·연말·주차 경계, 긴 메뉴·큰 글씨·다크 모드·TalkBack 확인. 출처·README·라이선스 고지·외부 전송 안내 갱신.

최초 범위: 학교 연결, 오늘 중식, 날짜별 세 끼, 열량·알레르기 번호·영양·원산지 상세, 오프라인 캐시. 월간 달력·급식 알림·위젯·개인별 알레르기 강조는 후속으로 둔다. 기능 추가 개발 버전은 `0.2.0-beta`로 설정했다. GitHub 릴리즈 게시와 배포용 인증키를 사용한 전체 주간 검증은 별도다.
