# QnmsbChange 문자열 필드 대응

기준: main `4e001e595be66268ad5e88aaead512f424deb6c4`.

## 문제와 원인

2026-11-12 Parser Health 실행 43125524927은 서비스 페이지·학교 검색 단계에서
실패했다. 갱신 시각 표현에 QnmsbChange 래퍼가 생겼고, 학교 코드와 이름·지역,
교사·과목·날짜에 Base64 → 반복 바이트 XOR → CP949 인코딩이 추가됐다.
시작일·일과시간도 동적으로 번호가 바뀌는 자료 필드로 이동했다.

## 구현

- 기존 HMAC 검증·AES 복호화 이후에만 JSON 필드를 정규화한다.
- 알려진 변환 함수 전체 문법과 변수 참조 관계를 검사한다. 공식 함수의 한글
  변수명을 Java의 ASCII 기본 `\w`로 처리하면 실패하므로 Unicode 문자 범주를 사용한다.
- 리터럴 키는 1~256바이트로 제한하고, 시작일·일과시간 참조는 각각 하나만 허용한다.
  운영 키·자료 번호를 고정하거나 JavaScript를 실행하지 않는다.
- Base64의 정규 표현과 CP949의 잘못된 바이트를 엄격히 검사한다. 오류에 원문·키를
  첨부하지 않으며 서비스 코드의 진단 문자열에서도 복원 키를 숨긴다.
- 가변 학교 코드 열만 복원한다. 미사용 미끼 열은 해석하지 않는다. 안내 행은 마지막
  값이 인코딩된 0인 경우도 제외한다.
- 교사·과목·갱신 시각·날짜를 복원하고 과목 0번 숫자 표식은 빈 문자열로 정규화한다.
  일과시간은 기존 교시 접두사와 순서 기반 HH:mm 형식을 모두 읽는다.
- 인코딩 문법이 없는 기존 페이지는 원래 처리 경로를 사용한다. UI·버전·의존성은
  변경하지 않는다.

## 검증 범위

새 합성 회귀 사례가 기존 구현에서 StructureChanged로 실패하는 것을 먼저 확인했다.
고정 문자열 벡터는 pycomcigan PR 18의 독립 Node.js·iconv 생성 자료를 참조한다.
학교·안내 행, CP949 확장 문자, 잘못된 Base64·문자열 타입·함수 문법·키 길이,
한글 변수명, 동적 필드 변경, 입력 불변성, 날짜·시작 시간·교사·과목 복원 및
HMAC 오류가 필드 정규화보다 먼저 거부되는지를 검증한다.

실서버 검증: 정확한 중일고등학교 검색, 빈 검색, 2026-11-09 시작 시간표의 34개 수업,
2026-11-16 시작 시간표의 18개 수업을 확인했다. 운영 키·교사명·과목명은 기록하지 않는다.

로컬 APK 빌드·서명·설치·Lint는 수행하지 않는다. PR의 기존 Android 및 Parser Health
Actions 검증은 정상 실행하며, 로컬 JVM 검증 결과와 Actions 결과를 구분해 기록한다.
